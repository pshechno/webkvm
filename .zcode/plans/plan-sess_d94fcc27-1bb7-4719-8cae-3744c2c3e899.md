# Модификация WebKVM под твои требования

Исследование подтвердило причины всех 9 пунктов. План — по приоритету (баги → фичи → UX).

## 1. Реалтайм-статус VM (п.1) — чинить SSE-конвейер
Реалтайм в коде формально есть (`/api/events` SSE + `libvirt/events.go` lifecycle events), но у тебя не обновляется ничего — значит где-то разрыв. Работы:
- Проверить/починить регистрацию libvirt lifecycle event callbacks (`backend/internal/libvirt/events.go`) — в т.ч. для событий при внешних изменениях (virsh, выключение изнутри гостя) и после действий webkvm.
- Прод диагностик: логировать путь события domain→hub→SSE; убедиться, что `VmList.svelte` патчит статус (сейчас патчит только при `onVmState` — проверить матчинг по id/имени).
- Добавить fallback: если SSE-соединение рестартует, полный `loadVMs()` после reconnect (сейчас может оставаться устаревший список).

## 2. VNC-баг «в двух окнах одна VM» (п.6) — найдена причина
`GetGraphicsInfo` (`backend/internal/libvirt/domain.go:~1998`): при `port='-1'` (autoport, inactive XML) молча подставляется дефолт **5900** — оба прокси dial'ят порт первой VM.
- Читать live XML (`GetXMLDesc` с флагом live), при `port <= 0` возвращать ошибку вместо дефолта 5900.
- Добавить `Cache-Control: no-store` на страницу `/console/{id}` (`backend/internal/api/console.go`).
- Логировать реальный порт в `vnc_proxy_dialing`.

## 3. Откат на единственный снапшот (п.8) — однострочный фикс
`VmDetail.svelte:6477` — кнопка Revert спрятана условием `{#if !node.current}`. Убрать условие (backend `RevertToSnapshot(0)` работает и на current), оставить confirm.

## 4. Быстрые снапшоты из списка VM (п.7)
В `VmList.svelte` (dropdown действий карточки, ~стр. 1892–2146):
- пункт «Снапшот» — быстрое создание с именем по умолчанию;
- подменю «Откатиться на снапшот» — список снапшотов VM + revert (confirm, требует shutoff как сейчас).
API уже всё позволяет.

## 5. Автоeject ISO после выключения (п.5)
- Пер-VM флаг в VM meta (`models/types.go`, `UpdateVMMeta` уже есть, router.go:285).
- Хук в `ShutdownVM` (`api/vms.go:524`): после успешного shutdown — для cdrom-дисков вызвать `UpdateDiskSource(id, target, "")`.
- Чекбокс «Отключать ISO при выключении» в VmDetail (hardware/disks секция) + опция в VmCreate.

## 6. Быстрая смена ISO у VM (пп.3, 4)
- В VmDetail на вкладку overview (и в быстрый блок) вынести текущий ISO + кнопку «Сменить ISO» с dropdown'ом образов (сейчас спрятано в дисках).
- По п.4 «ISO занят одной VM»: в коде **нет** блокировок на совместное использование cdrom (`<readonly/>`, attach-путь без проверок) — воспроизведу твой кейс, если подтвердится, найду и уберу ограничение (возможно в `volumeInUse` или UI-уровне списка ISO).

## 7. Редактирование сетевых интерфейсов VM (п.2)
Backend-эндпоинты уже есть (`POST/PATCH/DELETE /api/vms/{id}/networks`): добавить/удалить, MAC, source, VLAN, link up/down.
- Проверить, что вкладка `net` в VmDetail полностью открывает эти возможности (добавить недостающий UI).
- Дополнить: смена модели NIC (virtio/e1000/...) — backend `UpdateNetworkIface` (`domain.go:3045`) + UI.

## 8. NVMe-диски (п.9)
Bus `nvme` есть в списке capabilities, но builder не генерирует корректный XML: для nvme нужен PCI address/namespace (`domain.go:2634–2693`).
- Добавить генерацию nvme-адресации в `AttachDisk`/`buildDiskXML`, target `vnvnme*n` по правилам libvirt.
- Разрешить выбор bus=nvme в VmCreate/VmDetail только когда libvirt поддерживает (проверка через capabilities).
- Протестировать на реальной VM (disk attach + boot).

## 9. UI: текущий стиль + быстрые действия (п.10)
Без переработки навигации: снапшоты/ISO/консоль/питание — прямо в списке VM (п.4, п.6 выше), плюс привычные для Proxmox/vSphere мелочи: индикатор состояния в реальном времени, быстрые фильтры по статусу.

## Порядок работы
Баги сначала: (1) SSE-реалтайм → (2) VNC → (3) revert единственного снапшота, затем фичи (4)–(8). Каждый пункт — отдельный коммит. После каждого шага — прогон `go test` и JS-тестов.
